# Re:Fit 사진 접수 · 운영자 조회 시연

홈커밍데이 게임처럼 **운영 노트북에서 서버를 실행하고 HTTPS 링크를 QR로 안내**합니다. 참가자는 휴대폰에서 촬영 안내를 읽고 이름 또는 별명·측정할 손·사진 두 장을 제출합니다. 운영자는 별도 화면에서 사용자를 선택해 사진 위 측정 위치와 11개 치수를 확인합니다.

## 운영 노트북에서 시작

1. Windows x64와 64비트 Python 3.12가 필요합니다. Python Launcher도 설치하세요. ZIP을 전부 한 폴더에 풀어 주세요. 측정 모델은 포함돼 있습니다.
2. 처음 한 번 `INSTALL_FIRST.cmd`를 실행합니다. 패키지와 검증된 Cloudflare 실행 파일을 다운로드하고 모델·한글 글꼴을 검사합니다.
3. `START_DEMO.cmd`를 실행하면 시작 페이지 두 개가 열립니다.

| 시작 파일 | 용도 | 공유 대상 |
|---|---|---|
| `DEMO_JOIN.html` | 참가자 접속 QR·사진 제출 링크·APK 연결 설정 | 참가자에게 QR만 안내 |
| `DEMO_OPERATOR.html` | 운영자 화면 링크·관리자 키 | 운영자만 보관 |

4. 운영자는 `DEMO_OPERATOR.html`의 관리자 키를 복사하고 **사용자 목록과 측정 결과 열기**를 눌러 붙여 넣으세요. 참가자 QR의 연결키로는 운영자 화면을 열 수 없습니다.
5. 참가자 휴대폰을 LTE/5G로 바꾸고 QR 접속·사진 제출·운영자 목록 등장을 확인하세요. 주소 표시만으로 외부 접속이 검증된 것은 아닙니다.
6. 행사 중 전원·인터넷·실행 창을 유지하고 노트북 덮개도 열어 두세요. 종료는 실행 창에서 Ctrl+C입니다. 다시 실행하면 임시 HTTPS 주소가 바뀌므로 새 QR을 안내하세요. 이미 접수된 사용자 정보와 결과는 같은 폴더에 남습니다.

Cloudflare Quick Tunnel의 임시 주소를 사용하는 시연용입니다. 노트북이 꺼지면 사진 접수·조회가 중단됩니다. 실행 폴더를 공개 웹 폴더로 옮기거나 통째로 공유하지 마세요.

## 참가자 흐름

1. QR 접속 → 촬영 안내 확인.
2. 이름 또는 별명과 왼손·오른손 입력.
3. 위 사진·측면 사진을 카메라로 찍거나 앨범에서 선택.
4. 원본 사진·이름·측정 결과가 운영 노트북에 보관되는 것에 동의하고 제출.
5. 접수번호와 분석 대기/분석 중/완료/확인 필요 상태 확인.

갤럭시 Chrome과 아이폰·아이패드 Safari/Bluefy에서 사진을 제출합니다. 카메라 권한과 파일 선택 방식은 각 브라우저에서 직접 확인해야 합니다. 새로고침해도 서버 접수 기록은 남지만 휴대폰의 상태 확인 정보는 사라집니다. 이름이 같아도 서로 다른 접수번호로 구분합니다. 재접수는 새 기록이며, 이전 기록 삭제는 운영자에게 요청하세요.

촬영은 손 전체·손목 아래 약 10cm·기준 카드 네 모서리를 담습니다. 손등이 위인 사진과 새끼손가락 쪽이 바닥인 측면 사진을 같은 손으로 찍으세요. 옆 사진은 엄지를 손바닥 쪽에 붙이세요. 무늬 없는 흰 배경에서 1배율·수직 촬영을 권합니다. 85.6×54mm 규격 카드의 개인정보가 없는 뒷면을 쓰세요. JPG/PNG/갤럭시 모션포토 JPG(MPO)/아이폰 HEIC를 받으며, 원본 바이트와 EXIF를 그대로 서버에 보관합니다. 한 장 20MiB·2400만 화소까지 받습니다.

## 운영자 결과 조회

운영자 화면 주소는 생성된 HTTPS 주소 뒤에 `/operator`입니다. 관리자 키는 화면에 직접 입력하며 URL이나 브라우저 저장소에 넣지 않습니다. 새로고침하면 다시 입력하세요. 자리를 비울 때 **잠그기**를 누르세요.

이름·접수번호 검색과 사용자 선택 → 위/측면 사진의 측정선 → 색상 번호별 11개 치수(mm)를 표시합니다. 전체 보고서 JPG·치수 CSV·사진 원본을 받을 수 있습니다. 목록은 5초마다 갱신됩니다. 동시에 여러 사람이 제출하면 최대 20건을 순서대로 분석합니다. 보관 한도는 500건이며 운영자가 불필요한 접수를 지워 관리하세요. 단일 서버 프로세스로만 실행합니다.

기존 치수 정의를 유지합니다. 특히 **⑨는 5번에서 새끼 쪽 손 테두리까지의 가로 길이**이며 예시 이미지의 17↔5 직선 거리로 바꾸지 않았습니다. 측정 실패 항목을 예시 값으로 대체하지 않습니다. 11개 유효 치수와 보고서가 모두 있어야 측정 완료가 됩니다. 실패 시 사유를 확인하고 재촬영하세요. 서버 재시작으로 중단된 분석은 확인 필요 상태로 남으므로 다시 제출하세요.

**이 접수 삭제**를 누르고 확인하면 이름·원본 사진·미리보기·보고서·치수가 서버에서 함께 삭제됩니다. 분석 대기/진행 중에는 삭제할 수 없습니다. 운영자가 내려받은 파일은 별도로 관리해야 합니다. 자동 삭제 기한은 없으므로 시연 후 운영자가 기록을 정리하세요.

## 기존 갤럭시 APK와 센서

기존 APK는 `DEMO_JOIN.html`의 HTTPS 주소와 연결키를 측정 서버 설정에 입력해 쓸 수 있습니다. **이번 사용자 목록에는 웹의 참가자 접수로 제출한 기록이 모입니다. 기존 APK에서 측정한 기록을 자동으로 이 목록에 합치지는 않습니다.**

기존 사진·BLE·운동 시연은 `DEMO_JOIN.html`의 별도 센서 시연 링크(`/demo`)로 유지합니다. 갤럭시 Chrome, 아이폰·아이패드 Bluefy가 필요합니다. 실제 서비스 UUID·알림 특성 UUID와 signed INT16 little-endian 전송 형식 확인이 필요하며, 임의 센서 UUID/보정값/모터 명령은 넣지 않았습니다. 최근 2초간 수신이 없으면 실제 센서값 표시를 비웁니다.

## 보관 위치와 검증 범위

접속키·관리자 키는 `.demo-private/credentials.json`에 생성되고, 사용자 기록과 사진은 `vision/out/server/participants` 아래 SQLite와 파일로 보관됩니다. 배포 ZIP에는 실제 키나 사용자 사진이 없습니다. 별도 서버 계정이나 데이터베이스 설치는 필요하지 않습니다.

기존 직접 측정 API의 원본 자동 보관은 꺼져 있지만, **이번 참가자 접수 기능은 요청한 사용자별 조회를 위해 원본을 저장합니다.** 사용자 화면에 이를 안내하고 동의를 받습니다.

자동 검사로 접수·권한 분리·원본 보존·중복 이름 구분·재시작·실패·누락 치수·대기 한도·삭제를 확인합니다. 네이티브 모델 기동과 빈 사진의 실패 처리는 Windows/Ubuntu CI에서 별도로 검사합니다. 실제 두 사진으로 측정이 성공하는지와 치수 정확성, 실기기 카메라·현장 외부 접속·BLE 수신은 리허설이 필요합니다. 확인되지 않은 부분을 시연 준비 완료로 간주하지 마세요.
