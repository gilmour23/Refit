# Re:Fit 사진 접수 · 운영자 조회 시연

홈커밍데이 게임처럼 **운영 노트북에서 서버를 실행하고 HTTPS 링크를 QR로 안내**합니다. 참가자는 휴대폰에서 촬영 안내를 읽고 이름 또는 별명·측정할 손·사진 두 장을 제출합니다. 운영자는 별도 화면에서 사용자를 선택해 사진 위 측정 위치와 11개 치수를 확인합니다.

## 운영 노트북에서 시작

1. Windows x64와 64비트 Python 3.12가 필요합니다. Python Launcher도 설치하세요. ZIP을 전부 한 폴더에 풀어 주세요. 측정 모델은 포함돼 있습니다.
2. 처음 한 번 `INSTALL_FIRST.cmd`를 실행합니다. 패키지와 검증된 Cloudflare 실행 파일을 다운로드하고 모델·한글 글꼴을 검사합니다.
3. `START_DEMO.cmd`를 실행하면 시작 페이지 두 개가 열립니다.

| 시작 파일 | 용도 | 공유 대상 |
|---|---|---|
| `DEMO_JOIN.html` | 참가자 접속 QR·사진 제출 링크·APK 연결 설정 | 참가자에게 QR만 안내 |
| `DEMO_OPERATOR.html` | 운영자 화면 링크·관리자 키 | 운영자만 보관 |

4. 운영자는 `DEMO_OPERATOR.html`의 관리자 키를 복사하고 **사용자 목록과 측정 결과 열기**를 눌러 붙여 넣으세요. 참가자 QR의 연결키로는 운영자 화면을 열 수 없습니다.
5. 참가자 휴대폰을 LTE/5G로 바꾸고 QR 접속·사진 제출·운영자 목록 등장을 확인하세요. 주소 표시만으로 외부 접속이 검증된 것은 아닙니다.
QR 안내 화면은 큰 QR·촬영 일러스트·참여 방법 세 가지로 구성됩니다. 갤럭시 APK 연결 주소·키와 센서 시연 링크는 하단 **운영용 연결 정보**를 펼쳐 확인합니다. QR과 일러스트는 화면 파일에 포함되어 별도 이미지 서버가 필요하지 않습니다. 참가자가 쓰는 휴대폰 촬영 화면은 유지합니다.

6. 행사 중 전원·인터넷·실행 창을 유지하고 노트북 덮개도 열어 두세요. 종료는 실행 창에서 Ctrl+C입니다. 다시 실행하면 임시 HTTPS 주소가 바뀌므로 새 QR을 안내하세요. 이미 접수된 사용자 정보와 결과는 같은 폴더에 남습니다.

Cloudflare Quick Tunnel의 임시 주소를 사용하는 시연용입니다. 노트북이 꺼지면 사진 접수·조회가 중단됩니다. 실행 폴더를 공개 웹 폴더로 옮기거나 통째로 공유하지 마세요.

## 화면 구성

제작자 화면은 Canva의 회계 관리 템플릿(EAFtH7bowPc)의 어두운 목록 영역과 이름·상태 정렬, 프로젝트 관리 템플릿(EAFU0YeYtJM)의 도구 모음·구분선을 참고해 정리했습니다. 검색과 검토 필터는 접수 목록 위에 두고 사진 옆에 폭·두께와 길이 기준을 표시합니다.

참가자 촬영 화면은 승인한 일러스트 시안을 유지합니다. 제작자 PC 웹사이트는 접수 목록·중앙 사진 작업 영역·오른쪽 검토 패널·하단 작업 버튼으로 재구성했습니다. 사진 확인 → 치수 대조 → 검토 완료를 전환해도 사진은 같은 자리에 남습니다. 화면은 편집 가능한 HTML/CSS이며, 기존 측정 서버와 결과 버전을 사용합니다.

## 참가자 흐름

1. QR 접속 → 촬영 안내 확인.
2. 이름 또는 별명과 왼손·오른손 입력.
3. 손등·측면 사진 탭을 전환하면서 카메라로 찍거나 앨범에서 선택. 각 탭에서 촬영 자세 일러스트를 보고 같은 자세로 촬영합니다. 사진을 선택하면 예시 대신 본인 원본 미리보기가 표시되고, 손등 다음에는 측면 촬영 버튼이 나타납니다.
4. 원본 사진·이름·측정 결과가 운영 노트북에 보관되는 것에 동의하고 제출.
5. 접수번호와 분석 대기/분석 중/완료/확인 필요 상태 확인.

갤럭시 Chrome과 아이폰·아이패드 Safari/Bluefy에서 사진을 제출합니다. 카메라 권한과 파일 선택 방식은 각 브라우저에서 직접 확인해야 합니다. 접수 상태와 참가자 연결 정보는 현재 탭의 세션 저장소에 최대 12시간 보관해 새로고침 후 복원합니다. 공유 휴대폰에서는 ‘다른 사용자 새 접수’를 눌러 이전 상태 확인 정보를 지우세요. 관리자 키는 저장하지 않습니다. 운영자가 재촬영을 요청하면 이 화면에서 이유를 확인하고 요청받은 사진만 다시 제출합니다. 같은 접수번호에 새 버전이 생기며 이전 원본도 보존됩니다. 별도로 새 접수를 시작하면 새 접수번호입니다.

촬영은 손 전체·손목 아래 약 10cm·기준 카드 네 모서리를 담습니다. 손등이 위인 사진과 새끼손가락 쪽이 바닥인 측면 사진을 같은 손으로 찍으세요. 옆 사진은 엄지를 손바닥 쪽에 붙이세요. 무늬 없는 흰 배경에서 1배율·수직 촬영을 권합니다. 85.6×54mm 규격 카드의 개인정보가 없는 면을 쓰세요. JPG/PNG/갤럭시 모션포토 JPG(MPO)/아이폰 HEIC를 받으며, 원본 바이트와 EXIF를 그대로 서버에 보관합니다. 한 장 20MiB·2400만 화소까지 받습니다.

## 운영자 결과 조회

운영자 화면 주소는 생성된 HTTPS 주소 뒤에 `/operator`입니다. 관리자 키는 화면에 직접 입력하며 URL이나 브라우저 저장소에 넣지 않습니다. 새로고침하면 다시 입력하세요. 자리를 비울 때 **잠그기**를 누르세요.

사용자를 선택하면 사진과 11개 치수가 한 화면에 표시됩니다. 왼쪽에는 사용자 검색·목록, 가운데에는 손등/측면 사진, 오른쪽에는 네 위치의 폭·두께와 길이 세 개가 있습니다. 단계를 옮기거나 검토 승인을 누를 필요가 없습니다. 참가자에게도 계산 완료를 표시하며 별도 승인 단계를 기다리게 하지 않습니다.

- **자료 받기**: 측정표 JPG와 치수 CSV. 파일명에 사용자·손 방향·접수번호·결과 버전이 포함됩니다.
- **더보기**: 이전 결과 선택, 원본 사진 받기, 접수 삭제. 과거 결과는 읽기 전용입니다.
- **보정 도구**: 카드 모서리·손목 0점 지정, 원본 재분석, 재촬영 요청, 사진 확대·원본 보기·계산 기준. 기본 화면에서는 접혀 있습니다.

치수를 누르면 해당 손등/측면 사진으로 전환하며 실제 계산에 사용한 선을 강조합니다. 보정을 시작할 때만 사진 위에 점 선택 안내와 저장·취소 버튼이 나타납니다. 보정 중에도 치수표는 유지되고 사진 탭을 바꿔도 선택한 점은 남습니다. 카드 네 점 또는 손목 한 점을 완성해야 저장할 수 있습니다. 저장하지 않은 보정이 있을 때는 이전 계산 자료 받기를 막습니다.

보정 저장·재분석은 기존 Python 측정기로 새 결과 버전을 만들며 과거 원본·결과는 남습니다. 별도 확인 팝업 없이 실행합니다. 선택한 접수를 변경하면서 저장하지 않은 보정을 버릴 때와 접수를 삭제할 때는 확인이 필요합니다. 위치를 자동 검출로 돌릴 수도 있습니다. 카드 지정은 배율 계산이며 원근 왜곡 전체를 교정하지는 않습니다.

측정 실패 이유는 사진 위에 표시하고 촬영·EXIF 등의 경고는 치수표 아래 **측정 안내**에서 펼칩니다. 실패한 항목에 예시 값을 채우지 않습니다. 특히 ⑨는 5번에서 새끼 쪽 손 테두리까지의 가로 길이이며 17↔5 직선 거리로 바꾸지 않았습니다. 11개 유효 치수와 보고서가 있어야 계산 완료로 처리합니다. 사진의 측정선과 실제 치수의 대조는 여전히 필요합니다.

목록은 5초마다 갱신됩니다. 30건을 초과하면 페이지 이동이 나타납니다. 최대 20건을 순서대로 분석하며 보관 한도는 500건입니다. 단일 서버 프로세스로 실행합니다. 기존 원본·기록은 그대로 유지하고 승인 화면만 제거했으므로 데이터베이스를 이전할 필요가 없습니다.

**11월 8일 측정 수정:** 팔 주변과 카드 주변의 배경이 다른 경우, 카드 가까이의 배경과 사각형 경계를 함께 사용합니다. 카드 인쇄·반사 때문에 일부만 다시 검출되면 유효한 전체 카드 모서리를 유지합니다. 추가된 보완 검출은 명확한 후보 하나가 있을 때만 축척을 반환합니다. 기존 색상 검출은 먼저 실행되므로 사진에는 기준 카드 한 장만 놓으세요. 손 검출 실패, 나뭇결이 손 윤곽에 붙는 경우, 손목 아래가 잘린 사진까지 해결된 것은 아닙니다. 이 경우 사진을 바꾸거나 카드 모서리를 직접 지정해 확인하세요. 카드 보정으로 손 인식 실패를 복구할 수는 없습니다.

업데이트 후 실패한 접수를 선택해 **보정 도구 → 원본 사진 다시 분석**을 누르면 기존 두 사진과 저장된 보정 좌표로 새 결과 버전을 만듭니다. 사진을 다시 올릴 필요는 없습니다. 과거 버전은 보존됩니다. 502는 사진 검출 실패와 별개인 HTTP 서버/터널 오류입니다. 반복되면 실행 창과 `logs/server.log`, `logs/tunnel.log`를 확인하세요. 공유할 때 접속키와 개인 정보는 지우세요.

### 결과 버전·재촬영

**더보기 → 이전 결과**로 과거 원본·치수·보고서를 열 수 있습니다. 과거 버전에서는 보정·재분석·접수 삭제를 할 수 없습니다.

재촬영 요청에서 손등/측면과 이유를 지정하면 참가자의 기존 접수 화면에 표시됩니다. 다른 사진은 원본 그대로 재사용하고 교체된 사진의 이전 보정 좌표는 버립니다. 접수당 최대 20개 버전을 보관합니다. 이전 폴더와 SQLite는 자동으로 첫 버전으로 인식합니다. 새 ZIP을 별도 폴더에 풀면 기존 기록은 자동으로 옮겨지지 않으므로, 서버 종료 후 기존 실행 폴더의 소스만 교체하고 `.demo-private`와 `vision/out`은 보존하세요. 업데이트 전에 실행 폴더를 백업하세요.

**더보기 → 이 접수 삭제**를 누르고 확인하면 이름·원본 사진·미리보기·보고서·치수가 서버에서 함께 삭제됩니다. 분석 대기/진행 중에는 삭제할 수 없습니다. 운영자가 내려받은 파일은 별도로 관리해야 합니다. 자동 삭제 기한은 없으므로 시연 후 운영자가 기록을 정리하세요.

## 기존 갤럭시 APK와 센서

기존 APK는 `DEMO_JOIN.html`의 HTTPS 주소와 연결키를 측정 서버 설정에 입력해 쓸 수 있습니다. **이번 사용자 목록에는 웹의 참가자 접수로 제출한 기록이 모입니다. 기존 APK에서 측정한 기록을 자동으로 이 목록에 합치지는 않습니다.**

기존 사진·BLE·운동 시연은 `DEMO_JOIN.html`의 별도 센서 시연 링크(`/demo`)로 유지합니다. 갤럭시 Chrome, 아이폰·아이패드 Bluefy가 필요합니다. 실제 서비스 UUID·알림 특성 UUID와 signed INT16 little-endian 전송 형식 확인이 필요하며, 임의 센서 UUID/보정값/모터 명령은 넣지 않았습니다. 최근 2초간 수신이 없으면 실제 센서값 표시를 비웁니다.

## 보관 위치와 검증 범위

접속키·관리자 키는 `.demo-private/credentials.json`에 생성되고, 사용자 기록과 사진은 `vision/out/server/participants` 아래 SQLite와 파일로 보관됩니다. 배포 ZIP에는 실제 키나 사용자 사진이 없습니다. 별도 서버 계정이나 데이터베이스 설치는 필요하지 않습니다.

기존 직접 측정 API의 원본 자동 보관은 꺼져 있지만, **이번 참가자 접수 기능은 요청한 사용자별 조회를 위해 원본을 저장합니다.** 사용자 화면에 이를 안내하고 동의를 받습니다.

자동 검사로 접수·권한 분리·원본 보존·중복 이름 구분·재시작·실패·누락 치수·대기 한도·삭제를 확인합니다. 네이티브 모델 기동과 빈 사진의 실패 처리는 Windows/Ubuntu CI에서 별도로 검사합니다. 실제 두 사진으로 측정이 성공하는지와 치수 정확성, 실기기 카메라·현장 외부 접속·BLE 수신은 리허설이 필요합니다. 확인되지 않은 부분을 시연 준비 완료로 간주하지 마세요.
