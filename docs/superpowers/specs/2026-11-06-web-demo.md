# ReFit mobile web demonstration

Goal: reproduce the existing photo-measurement and live BLE reception flows on Galaxy Chrome and iPhone/iPad Bluefy for the November 11 demonstration. Both real functions are required; neither has been validated on the user's devices yet.

Chosen hosting: the user's Homecoming game pattern, one laptop Python server plus an accountless Cloudflare HTTPS tunnel. Serve the web UI and measurement API on the same origin. Keep existing APK API routes compatible so Galaxy can use either the web or APK. The operator laptop must stay powered and online.

Alternatives considered: native iOS/TestFlight adds a separate port/signing process; a static hosted UI alone cannot run the Python/OpenCV/MediaPipe pipeline. Do not modify the rehabilitation-center site.

Keep current navy/teal styling. Three primary areas: photo measurement, sensor, guided exercise. Read original JPEG/PNG bytes and EXIF, including Galaxy JPEG/MPO motion-photo containers. No invented card coordinates, no example result substituted for failure. Show all eleven valid dimensions and report, acknowledge warnings before registration.

BLE: user-configured real service/notify UUIDs and explicit confirmation of signed INT16_LE raw packets. Subscribe to actual GATT notifications. Distinguish subscription from actual sample reception, disconnect from pause, stale data from zero. No invented microvolt calibration, clinical recovery interpretation or motor writes. Exercise uses actual received data and indicates missing signal.

Security: automatic per-install upload/admin key generation outside source; only upload key distributed to participants. Static UI public, protected API unchanged, admin report access separate. Session-only in-memory browser key, optional explicit join fragment cleared from address immediately. Do not store photos/reports in localStorage. Server input body/image bounds retained. Stop tunnel on shutdown.

Evidence: unit/API tests, actual supplied top/side image inference on this runtime, browser UI verification when available. Physical BLE and iOS/Galaxy behavior require the team's real hardware; no claim of real-device completion without those checks.
