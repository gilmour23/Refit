## Retry policy and decisions

- Retry on account screen startup, app foreground, authenticated SDK readiness, session completion, and explicit history action.
- Calls arriving during active sync request a later pending pass. No periodic/background retry loop is introduced.
- `updatedAt` describes session content; local sync-state changes do not change it. Completed V1 summaries are immutable.
- Process death is recovered when the app is reopened. Continuous background sync and cross-device history download remain outside the approved V1 upload policy.
- Server RLS remains the final authority if the shared SDK token changes during an HTTP request. Rows always retain their original owner; a different account cannot claim them.
