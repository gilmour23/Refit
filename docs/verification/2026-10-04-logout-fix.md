# ReFit V0.4.1 로그아웃 보안 수정 검증

검증일: 2026-10-04 KST. 대상: feature/refit-v1-foundation의 로그아웃 수정.

## 결과

로그아웃 요청이 서버 응답을 기다리는 동안 이전 계정 화면과 운동 상태를 사용할 수 있던 중간 위험을 수정했다. 전체 테스트 38개가 통과했고 실패·오류·생략은 0개다. Supabase 연결 설정을 포함한 Debug APK 빌드와 서명 검증에 성공했다. 앱 버전은 0.4.1, versionCode는 5다.

## 수정 동작

- AuthViewModel은 로그아웃 호출 시 동기적으로 계정 ViewModelStore를 지우고 Unauthenticated를 게시한다. 기존 측정 연결, 운동 결과, 계정의 coroutine 작업은 이 정리 경로로 종료된다.
- 로컬 세션은 HTTP 요청 전에 삭제한다. 기존 JWT만 해당 요청의 메모리 변수로 유지해 SDK의 명시적 토큰 API로 POST /auth/v1/logout?scope=local을 요청한다. 추가 관리자 키를 사용하지 않는다.
- 서버 요청은 10초로 제한한다. 오프라인 또는 시간 초과 때 계정 화면은 닫힌 상태를 유지하며 서버 해지를 확인하지 못했다는 안내를 표시한다. 로컬 정리는 NonCancellable에서 수행한다.
- 명시적 로그아웃 후 SDK의 Loading/Authenticated 복원 이벤트로 화면을 다시 열지 않는다. 새 자격 증명 제출이 성공한 뒤 현재 SDK 상태를 받아들인다. 일반적인 동일 계정의 일시적 Loading과 오프라인 기록 접근은 기존 동작을 유지한다.
- 같은 화면의 중복 인증 요청을 차단한다. 저장소 인스턴스가 달라도 공유 인증 잠금으로 로그인·가입·로그아웃을 직렬화해 이전 로그아웃의 최종 정리가 새 로그인을 지우지 않게 한다.

## 직접 실행한 검증

실제 Supabase Kotlin 3.8.0 SDK, SharedPreferences, AuthViewModel, SessionViewModel, Room을 사용했다. 외부 HTTP 응답만 MockEngine에서 보류하거나 실패시켰다.

| 검사 | 결과 |
| --- | --- |
| 지연된 로그아웃 HTTP | 호출 직후 로그인 화면 상태, 계정 ViewModel 제거, 측정 연결 종료, 운동 상태 초기화 |
| 서버 응답 전 로컬 삭제 | 메모리·저장소 세션 없음; 같은 저장소로 만든 새 SDK 클라이언트도 로그인 복원하지 않음 |
| 서버 요청의 토큰과 범위 | 이전 사용자 JWT가 Authorization에 전달됨; scope=local |
| 지연된 SDK 이벤트 | Loading과 이전 사용자 Authenticated를 보내도 계정 화면 열리지 않음 |
| 중복 로그아웃·로그인·가입 | 진행 중 추가 HTTP 인증 요청 차단; 완료 후 사용자 B 로그인 가능 |
| 원격 요청 취소 | 메모리와 저장소 세션 삭제 유지 |
| 저장소 토큰 읽기 중 취소 | SDK의 실제 loadSessionOrNull 예외 처리 뒤 로컬 정리 수행 |
| 서버가 응답하지 않음 | 10초 제한 후 로그인 입력 재활성화, 계정 화면 닫힘 유지 |
| 같은 클라이언트의 두 저장소 | 첫 로그아웃 중 두 번째 로그인은 대기; 완료 후 B 세션이 메모리·저장소에 유지됨 |
| 기존 인증·계정 분리·DB·동기화·신호 처리 회귀 | 전체 38개 통과 |
| 독립 코드 검토 | 공유 클라이언트의 정리 경쟁을 추가로 발견해 수정; 최종 차단 사항 없음 |

최초 신규 회귀 테스트 3개는 수정 전에 예상한 이유로 실패했다. 공유 저장소 경쟁 회귀 테스트도 공통 잠금 적용 전에 실패했다. 테스트의 가상 시간과 SDK의 실제 저장소 dispatcher가 섞여 생긴 시간 초과는 테스트 실행 방식으로 해결했다. 최종 검증 명령은 `:app:testDebugUnitTest :app:assembleDebug`다.

SDK의 정확한 3.8.0 Maven sources 및 같은 Git tag의 AuthImpl/AdminApi 구현을 확인했다. admin.signOut(jwt, LOCAL)은 전달된 사용자 JWT를 쓰는 logout 엔드포인트이며 서버 관리자 권한의 사용자 관리 작업을 호출하지 않는다.

- 실제 프로젝트 URL과 publishable key 1개 포함. sb_secret 키와 service_role 주장 문자열은 발견하지 않았다.
- 새 Debug 인증서 SHA-256: ccc640c00bb3e199b9e5f5def344fd9e7ca7dfd815e61764777036df8aeb6ace

이전 0.4 APK와 Debug 서명이 다르다. 기존 앱 위에 설치하면 Android가 업데이트를 거절할 수 있다. 이 경우 기존 테스트 앱을 삭제한 뒤 새 APK를 설치해야 하며, 앱 삭제는 기기 내 재활 기록도 삭제한다. 기록이 있는 기기는 삭제 전에 보존 방법을 확인한다. 정식 배포 서명은 아직 구성하지 않았다.

## 남은 범위

실제 사용자 JWT의 서버 해지, 이메일 인증, 실기기 수명주기와 BLE 센서 동작은 이번 SDK 회귀 검사로 대체하지 않는다. 기기 내 추가 암호화와 릴리스 서명은 기존 보안 점검의 배포 전 과제로 남는다. 이미 발급된 access token은 서버의 만료/세션 정책에 따라 처리되므로 이번 로컬 접근 종료를 모든 토큰의 즉시 서버 무효화로 표현하지 않는다.

화면 디자인은 이 수정에서 변경하지 않았다. 디자인 검토는 동일한 화면을 제공하는 V0.4.1 개발 테스트 APK로 진행할 수 있다.
