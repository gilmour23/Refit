# Re:Fit 0.5.0 환자 안내 흐름

## 변경 범위

환자에게 필요한 동작 안내·휴식·진행 시간을 중심으로 로그인, 홈, 준비, 진행, 결과, 기록과 상세 화면을 다시 구성했다. 손목을 실제로 움직이지 못하더라도 안내 구간을 진행할 수 있다. 구간 경과를 동작 성공으로 판정하지 않으며 회복률과 이전 세션 대비 RMS 변화율을 제거했다.

- 준비 → 손목 폄 시도 → 휴식 → 자동 종료. 마지막 휴식도 안내 시간에 포함한다.
- 일시정지·재개, 중간 종료 확인, 백그라운드 진입 시 일시정지.
- 연결 대기 중 요청된 일시정지는 연결 완료 후에도 유지한다.
- 정지 중 경과 시간과 EMG 샘플은 결과에서 제외한다.
- 별도 화면의 시간 설정과 범위 검사. 기본 4초·6초·3회는 데모이며 운동 처방이 아니다.
- 결과의 운동 후 상태를 계정 소유권을 검사해 저장한다.
- 기록은 날짜·진행 시간·안내 구간·운동 후 상태·데이터 출처를 표시한다.
- 기록 목록의 상태 갱신은 원자적으로 처리해 동시에 저장되는 결과와 불편감 상태를 덮지 않도록 했다.
- RMS·MAV·Peak는 선택한 측정 상세에서만 공개한다. 그래프의 자동 축척은 시각적 표시용이다.
- Noto Sans KR의 정적 400·600·700 글꼴을 포함하고 OFL 라이선스를 동봉했다.

## 데이터와 보안

Room 3에 안내 시간, 구간 수, 중간 종료, 데이터 출처와 불편감 필드를 추가했다. 1→2→3 마이그레이션을 유지한다. 기존 기록의 없는 필드는 null, 출처는 unknown이며 추정한 운동 성과를 채우지 않는다.

새 메타데이터는 기기 내 계정별 기록이다. Supabase는 기존 세션 요약만 동기화한다. 서버 스키마·RLS·인증·로그아웃 경로는 변경하지 않았다. 다른 기기에서 새 메타데이터를 내려받는 기능은 없다.

Debug APK의 Compose 테스트용 Activity와 PreviewActivity는 exported=false로 덮어써 외부 앱에서 실행할 수 없게 했다.

## 실행 검사

전체 단위·통합·Compose 화면 검사 51개가 통과했다. 자동 종료, 정지 중 시간·고신호 제외, 조기 종료가 성공 횟수를 만들지 않는지, 불편감의 DB 재개방 후 유지와 다른 계정의 수정 차단을 확인했다. 기존 인증·로그아웃·계정 분리·동기화·DB·신호 처리 회귀 검사도 포함한다.

Compose 화면 검사는 홈→준비, 시도→정지→재개→휴식, 결과의 상세 수치 공개, 불편감 선택, 기록→상세, 설정 입력 검사와 글자 크기 1.4배에서 주요 행동 버튼의 가시성을 확인한다. Robolectric SDK 33 Native Graphics와 Roborazzi를 사용해 실제 Compose 코드에서 12개 화면·상태를 렌더링했다. 캡처의 날짜·신호·기록은 예시 데이터이다. 운영체제 상태 표시줄·탐색 표시줄을 합성하지 않았다.

초기 시간 안내 회귀 검사는 수정 전 무한 실행 때문에 실패했다. 정적 글꼴 교체 후 Kotlin의 증분 컴파일이 기존 선언을 중복 인식한 문제는 증분 컴파일을 끄고 재검증했다. 설정 AlertDialog의 Robolectric 대기 문제는 단독 렌더링과 SDK 28에서도 재현됐으며 원인을 확정하지 못했다. 최종 설정은 큰 입력칸과 고정 적용 버튼을 둔 별도 화면으로 구현하고 검증했다.

검증 명령:

```sh
gradle :app:testDebugUnitTest :app:assembleDebug -Pkotlin.incremental=false
git diff --check
```

## 설치와 남은 확인

versionCode 6 / versionName 0.5.0이다. 기존 0.4.1 APK와 동일한 개발 서명 키를 사용한다. 해당 APK 위에 업데이트하도록 만든 버전이며 삭제 후 재설치는 기기 내 기록을 잃게 하므로 권장하지 않는다.

- APK 크기: 18,314,093 bytes
- APK SHA-256: `7037a4ee72637b344b33fe7a6925e1a0283a215a8a6a2f391884a55eb5c3025c`
- 개발 인증서 SHA-256: `ccc640c00bb3e199b9e5f5def344fd9e7ca7dfd815e61764777036df8aeb6ace`

현재 기본 소스는 MockEmgDataSource이고 화면과 기록에 데모로 표시한다. 실제 BLE 센서의 프로토콜·착용 상태·신호 품질은 확인되지 않았다. 한국어 음성은 기기의 TTS 지원에 의존한다. 실기기의 키보드·시스템 여백·수명주기·음성, 실제 환자·치료사의 사용성 및 임상적 적합성 검증은 별도로 필요하다.
